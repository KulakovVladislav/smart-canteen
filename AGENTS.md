# AGENTS.md

## Проект

«Умная столовая» — демонстрационный прототип школьной столовой: меню под жалобы, предзаказ, сводка для кухни, учёт
остатков, экономика и проверка себестоимости. Интерфейс — Streamlit (`web_app.py`), CLI — `app.py`, данные — SQLite в
`data/`.

Стек: Python 3, Streamlit, стандартная библиотека (`unittest`, `sqlite3`). React/Next.js не используется.

## Команды

- Установка: `python3 -m venv .venv && source .venv/bin/activate && pip install -r requirements.txt`
- Веб: `streamlit run web_app.py` (http://localhost:8501)
- CLI: `python app.py all|menu|preorder|budget-check`
- Тесты: `python -m unittest`
- База: `data/smart_canteen.db` (исключена из Git, создаётся автоматически)

## Общие правила

- Сначала изучать существующие соглашения и архитектуру; не переписывать работающие части без необходимости.
- Не создавать избыточную абстракцию и не дублировать компоненты.
- Соблюдать типизацию, читаемость, сопровождаемость и безопасность.
- Не игнорировать ошибки линтера, тестов и сборки; проверять реальные причины.
- Использовать установленные зависимости и инструменты проекта до добавления новых.
- Не утверждать, что функция работает, если она не проверена.
- Не добавлять секреты, токены и личные настройки в репозиторий.

## Дизайн

Цель — уровень качественного коммерческого продукта, а не стандартный результат генерации. Ориентир по качеству —
презентации Apple: продуманная типографика, выразительная композиция, свободное пространство, сильные визуальные
акценты, качественные изображения, аккуратные переходы и внимание к деталям. Не копировать Apple буквально, не
использовать чужие логотипы и фирменные материалы; дизайн должен иметь собственную визуальную идентичность под тему и
аудиторию.

Обязательно:

- Перед реализацией понимать назначение страницы и её пользователей.
- Избегать типовых AI-паттернов: одинаковых карточек в каждой секции, бессмысленных градиентов, чрезмерного количества
  теней, случайных декоративных элементов, шаблонных hero-блоков.
- Обдуманно выбирать шрифты, масштаб заголовков, сетку, палитру, отступы и иерархию.
- Создавать согласованную систему цветов, типографики, размеров, радиусов и компонентов.
- Использовать анимацию только там, где она усиливает восприятие или помогает понять действие.
- Обеспечить адаптивность для мобильных устройств и больших экранов.
- Учитывать доступность: контраст, клавиатурную навигацию, понятные состояния фокуса, семантику элементов.
- Предусматривать состояния загрузки, пустых результатов, ошибок и успешных действий.
- Все кнопки, ссылки, формы и элементы управления должны выполнять заявленные действия.
- Не подменять рабочую функциональность декоративными заглушками.
